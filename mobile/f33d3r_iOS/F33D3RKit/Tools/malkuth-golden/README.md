# Malkuth golden vectors

Three Go programs that generate and check the fixtures in
`Tests/F33D3RKitTests/Fixtures/malkuth_*.json`.

They exist because the Swift signing path cannot be proven against itself. An
encoder that agrees with its own tests and disagrees with the server produces
`400 cid mismatch` on every post, and a signature that verifies with the key
that made it proves nothing about whether `crypto/ecdsa` accepts it. So the
fixtures are generated by — and checked against — the Go the server actually
runs.

`workCanonicalPayload`, `verifyCID`, `workKinds`, `workEnvelope` and steps 2–6 of
`verifyMalkuthSig` are **copied verbatim** out of
`feed-engine/internal/handler/work_event.go`. Nothing here is re-derived. When
that file changes, update these copies from it and regenerate; if a copy has
drifted, the fixtures are describing a server that no longer exists.

The one substitution is `verifyMalkuthSig`'s step 1, which fetches the signing
key from Elohim Veni. That service is not running locally, so the vectors carry
the key instead — the same key the registration would have handed it.

## Programs

| | |
|---|---|
| `main.go` | canonical JSON + CID for a set of payloads covering every field shape. Asserts each result is a fixed point of the server's own unmarshal/re-marshal before emitting it. |
| `verify/` | `verify` checks Swift-made signatures with the Go verifier; `generate` produces Go-made signatures for Swift to check. |
| `envelope/` | runs a Swift-built `POST /events` body through `workEvent`'s whole admission sequence, stopping before `InsertWork`. |

## Regenerating

Needs Go and Xcode's toolchain.

```bash
cd F33D3RKit/Tools/malkuth-golden
FIXTURES=../../Tests/F33D3RKitTests/Fixtures

# 1. Canonical bytes and CIDs.
go run . golden_canonical.json
cp golden_canonical.json "$FIXTURES/malkuth_canonical.json"

# 2. Signatures, both directions.
cd ../..                                    # F33D3RKit
MALKUTH_EXPORT_DIR=Tools/malkuth-golden swift test --filter exportVectorsForGo
cd Tools/malkuth-golden
go run ./verify verify   vectors_from_swift.json    # must report 9/9
go run ./verify generate vectors_from_go.json
#   then merge: {note, go_version, from_go: <generate>.vectors,
#                from_swift: <verify>.verified.vectors} → malkuth_signatures.json

# 3. Whole envelopes through the server's admission path.
cd ../..
MALKUTH_EXPORT_DIR=Tools/malkuth-golden swift test --filter exportEnvelopesForGo
cd Tools/malkuth-golden
go run ./envelope envelopes_from_swift.json         # must report 13/13
#   then: envelopes_from_swift.json.verdicts + a note → malkuth_envelopes.json

cd ../.. && swift test
```

A regeneration that changes a CID without an intended change to
`workCanonicalPayload` is not a fixture to be updated — it is the encoder or the
struct having moved, and one of them is wrong.

This directory is outside `Sources/` and `Tests/`, so SwiftPM does not build it
and `swift test` does not need Go.
